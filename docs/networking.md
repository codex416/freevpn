# DNS、IPv4、IPv6 与 TUN：VPN 连接问题的基础排查

很多“VPN 连不上”“网站打不开”或“速度忽快忽慢”的问题，并不一定来自节点本身。DNS、IPv4、IPv6、系统代理、TUN 和路由方式都可能影响最终结果。

## DNS

DNS 负责把域名解析为 IP 地址。代理已经连接但域名解析异常时，常见表现包括部分网站打不开、连接超时或不同网络下表现不一致。

排查时可以比较：

- 系统 DNS 与客户端 DNS
- IPv4 和 IPv6 DNS 解析结果
- 直接访问 IP 与访问域名的差异
- 代理开启前后的解析行为

## IPv4 与 IPv6

现代网络可能同时具备 IPv4 和 IPv6。某些网络环境中 IPv6 路径质量与 IPv4 不同，因此“IPv4 正常、IPv6 异常”可能导致部分服务表现不稳定。

遇到异常时，可以分别测试 IPv4 和 IPv6 的连通性，再判断问题来自本地网络、DNS、客户端还是出口线路。

## TUN 模式

TUN 可以让客户端以虚拟网络接口的方式接管更多系统流量。它适合需要让不遵循传统系统代理设置的程序经过代理的场景。

启用 TUN 后如果出现异常，应重点检查：

- 客户端是否具有系统权限
- 路由表是否正确
- DNS 是否被正确接管
- IPv6 是否存在冲突
- 是否同时运行多个 VPN 或网络过滤工具

## 系统代理与 TUN 的区别

系统代理通常只影响遵循系统代理设置的应用；TUN 可以从更底层接管网络流量。因此某个程序“系统代理下不走代理”并不一定意味着节点异常。

## 常见排查顺序

1. 确认客户端已经连接。
2. 确认订阅或配置没有过期。
3. 测试 DNS 解析。
4. 分别检查 IPv4 / IPv6。
5. 检查系统代理或 TUN 状态。
6. 更换同地区的其他节点进行对比。
7. 最后判断目标网站或 API 是否存在自身故障或地区策略。
