# VPN 与代理连接故障排查

遇到 VPN 或代理异常时，不建议直接判断“节点坏了”。网络连接通常涉及客户端、配置、DNS、IP 协议、路由、出口和目标服务多个环节。

## 连接不上

先确认客户端是否真正建立连接，再检查：

1. 订阅是否仍然有效。
2. 节点地址、端口和配置是否正确。
3. 客户端是否拥有必要的 VPN 或系统权限。
4. DNS 是否能够正常解析。
5. IPv4 / IPv6 是否存在异常。
6. 是否同时运行其他 VPN、代理或网络过滤软件。

## 网站可以打开，但 API 或登录失败

网页、登录接口和 API 可能使用不同的域名、CDN、DNS 或网络链路。建议检查目标服务对应域名的解析结果，并确认客户端代理模式能够覆盖相关请求。

AI API 调试尤其需要注意：网页可访问并不代表 API 一定可用，还可能受到账号、地区和服务状态影响。

## 速度慢或频繁卡顿

不要只看延迟。还应比较：

- 下载和上传带宽
- 丢包率
- TCP / UDP 连接表现
- DNS 响应时间
- 出口地区
- 高峰时段服务器负载

可以先更换同一地区的其他节点。如果所有节点都慢，再检查本地运营商和 IPv4 / IPv6 路径。

## 只有部分网站打不开

如果只有一个或少数网站异常，优先判断 DNS、规则分流、出口 IP 或目标平台自身策略，而不是直接更换整个客户端。

检查：

- 域名是否被错误分流
- DNS 是否返回异常地址
- 目标域名是否经过代理
- IPv6 是否走了另一条路径
- 目标服务是否发生故障

## 订阅无法导入

确认订阅地址可以访问，并检查返回内容是否属于当前客户端支持的配置格式。不同客户端对 YAML、JSON、URI 和其他订阅格式的支持不同。

## TUN 开启后网络异常

重点检查系统权限、路由表、DNS 接管、IPv6 和其他 VPN 软件。必要时先关闭 TUN，确认传统系统代理是否正常，再逐项恢复设置。

## 最小化排查方法

当问题复杂时，先把变量减少到最少：

```text
客户端 → 单个节点 → 单个域名 → DNS → IPv4 / IPv6
```

先确认基础连接，再逐步加入规则、TUN、策略组和其他网络功能。
